Everything else has at least 2x headroom (`:147`, `:177`, `:186-199`, `:226`, `:244`, `:268`, `:286`, `:314`, `:336`, `:347`). Not measured: the callbacks with the real Consensus and coordinator pair (Consensus tests use `MockCoordinator`); estimated at about 70k for `proposeEpoch` plus `sign` and 50k to 85k for `attestTransaction` or `stageEpoch`, well inside 300k and 400k. The integration suites (2 and 3 validators) exercise both callbacks (baseline section 7). Foundry measures all calls of one test in one transaction, so later calls can see warm slots; the max case is the first, cold call. Answer: adequate.
- Q42 (sample database URL). Fresh node fails: F3-VAL-060 (E1).
- Q43 (`oracles` empty or wrong). ## Hypotheses considered and rejected

- Misspelled keys vanish under `deny_unknown_fields` with `flatten`: rejected, every tested typo fails at load (`R6-config-typos.txt`).
- `tracing::warn!(?effect, ...)` on a failed effect leaks key material through `Effect::GenerateNonces { key_share }`: rejected, `KeyShare` wraps frost `KeyPackage`, whose `signing_share` prints `<redacted>` (frost-core-3.0.0 `src/keys.rs:126-132`, `:631-635`); `Resume::Nonces` holds `SigningNonces`, which has its own redacting `Debug` (map section 2.1).
- Binding drift on any event or call: rejected (E1).
- Gas limits too low for Aegis 5 of 3: rejected (E1 for coordinator calls, estimate for callbacks).
- The callback context carries a trailing zero `signatureId` that breaks decoding: rejected, `onSignCompleted` decodes only the leading fields of `context[4:]` (`Consensus.sol:331-345`); selectors match (`stageEpoch` `0xea5eeafa`, `attestTransaction` `0xd49400f8`, E1).
- Topic collisions between watched contracts in the validator's decoder: rejected, no event name is shared between SentinelOracle, Consensus and the coordinator (grep of `event` declarations in `contracts/src`).
- The coordinator shared between the testnet and Aegis confuses the validator: rejected, key generation events are matched by group id and signing events by message or signature id, and signature ids are unique per group and sequence (`FROSTCoordinator.sol:515-516`).
- A startup RPC hiccup during staker queuing exits the process: rejected (Q44).
- Duplicate `SetValidatorStaker` is harmful: rejected (Q44).
- A restart warp also drops signing events while `GenerateNonces` or `UseNonces` is pending: rejected, `CollectNonceCommitments` and `CollectSigningShares` record peer events whether or not the effect resumed (`state/sign.rs:243-301`, `:399-412`).
- A live reorg (no restart) triggers F3-VAL-062 in practice: rejected as a practical trigger, live blocks arrive as separate RPC-backed updates and the local setup write resolves first.
- The Dockerfile should create the data directory: rejected, volumes create it, and its absence keeps a missing volume loud.

## Observations (plausible, not proven or below the finding bar)

- O1. An empty `oracles` list silently disables transaction attestation; the only signal is a `debug` line per proposal (`state/transactions.rs:32-39`). A startup warning would avoid three of five operators forgetting it. Informational.
- O2. Coordinator and Consensus events are dispatched without checking `log.address` (`state/mod.rs:396-441`); only `OracleResult` uses it. An allow-listed oracle contract that emits coordinator- or consensus-shaped events would be trusted as those contracts. An allow-listed oracle can already approve anything, so this is defense in depth (R1's Q4).
- O3. `/health` returns `OK` regardless of driver progress (`crates/core/src/observability/metrics.rs:8-11`, test `:76-78`); a validator stuck retrying RPC errors stays "healthy". Core, R2.
- O4. A typo inside a flattened table (`[index]`, `[transactions]`) reports "line 1, column 1" instead of the table position (`R6-config-typos.txt`). UX.
- O5. Neither the sample nor the handbook mentions `[index] start_block`; a validator first started after the genesis `KeyGen` without it never sees genesis (genesis liveness, A16).
- O6. A complaint mined after the complain deadline needs no response (`keygen.rs:704-710`, `:727-729`), yet onchain the plaintiff cannot confirm with an unresolved complaint (`FROSTParticipantMap.sol:220-223`). An honest plaintiff whose complaint was delayed more than 120 blocks is excluded at the confirm deadline while the accused stays. Needs the plaintiff's own transaction delayed; R4's Q30.
- O7. After an attestation timeout every validator submits the fallback (`state/sign.rs:670-688`); all but one revert with `AlreadyAttested`. Gas only.
- O8. Floating `rust:1-slim` builder and `debian:trixie-slim` runtime, running as root (Dockerfile:5, 24): hardening; a future `rust:1-slim` on a newer Debian could link a glibc the runtime lacks. R8's Q61.
- O9. The share-round deadline differs between the live and late-setup exits of the commitment round (`keygen.rs:132-133` vs `:251-252`); covered by F3-VAL-062 for the restart case, and noted by the authors at `keygen.rs:1247-1251`.

## Lessons for the head

- generic: A state machine that waits for an effect resume while events keep arriving must buffer the events or accept them in the waiting state; check every "wait for resume" state against batch replays where the resume cannot interleave.
- generic: Sample configs need a test that starts from the sample's values on an empty data directory, not only a parse test.
