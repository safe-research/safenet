## 4. Hypotheses considered and rejected (with the refuting citation)

- R1 **Warp catch-up advances expiry and staleness per log page** (would have bumped fees once per 100-block page and let expired actions through). Refuted: `initialize` sets `pending = head + 1` (`index/blocks.rs:250` via `update_next_pending_block`, `538-543`), `status()` derives `latest` from `pending` (`376-381`), and the queued synthetic `Uncle`/`Warp` are popped without touching `pending` (`385-389`); the index test asserts `BlockStatus { latest: 1000, safe: 997 }` immediately after the warp (`index/mod.rs:290-296`). The queue therefore sees the real head throughout a warp.
- R2 **A too-low nonce reading (lagging/forked backend) allocates a stale nonce, which the next correct reading marks executed, silently losing the action.** Guarded: allocation is `MAX(reading, MAX(nonce)+1)` (`tx/storage.rs:145-149`) and executed rows persist until `safe` (`250`), so within the reorg window the queue's own records dominate; defeating it needs all rows pruned plus a fork deeper than `max_reorg_depth`, which is fatal/out of scope (`index/blocks.rs:435-439`). Kept only as a "considered and rejected" note in F2-CORE-061.
- R3 **Two live rows sharing a nonce.** Impossible: the allocated nonce is strictly above `MAX(nonce)` over all rows, executed or not (`tx/storage.rs:146-149`); `record_submission ... WHERE nonce = ?` therefore hits one row (`176-184`).
- R4 **Nonce allocated and never released as a leak.** By design rows with `submitted_at IS NULL` are resubmitted every block (`tx/storage.rs:281-284, 296-297`), so nothing is stranded; the real issue is blocking, filed as F2-CORE-064.
- R5 **Double execution after a crash between broadcast and `record_submission`.** The row keeps its nonce; the retry reuses it (`tx/storage.rs:297`, `tx/types.rs:81-86` -> `bump(fresh, None)`); two transactions with one nonce cannot both mine.
- R6 **Crash between allocation and broadcast strands the nonce.** Same rows are picked up by `stale_submissions` (`tx/storage.rs:296-297`).
- R7 **The priority-fee cap does not apply to bumps (lead H6 sub-claim).** In ratio terms it does: if both inputs satisfy `p/mf <= c`, then `max(fresh_p, 1.1 prev_p) / max(fresh_mf, 1.1 prev_mf) <= c` for all four cases (`tx/fees.rs:39-56`), up to wei-scale `div_ceil` rounding. The doc note at `fees.rs:38` overstates it. What is true and filed (F2-CORE-060) is that a ratio bounds nothing absolutely.
- R8 **Overflow / divide-by-zero in `cap_priority_fee`.** `saturating_sub`, `saturating_mul`, `scaled_percent < PRECISION` guard (`tx/fees.rs:17-24`); `base + p' <= mf` (`29`). Non-finite caps: NaN -> 0 (F2-CORE-065), `inf` -> saturating cast -> no-op.
- R9 **`bump` yields `max_priority > max_fee`.** Component-wise max of two pairs each satisfying `p <= mf` preserves it (`tx/fees.rs:43-49`).
- R10 **`Error::NonceNotFound` reachable in production.** Single driver task; nothing deletes or re-nonces a row between `next_transaction`/`stale_submissions` and `record_submission` (`tx/mod.rs:204-216, 224-237`; `tx/storage.rs:198-200`).
- R11 **Same-height replacement (11 -> 11') slips past `previous == Some(status)` without an unmark.** The watcher regresses `pending` to the uncled number and returns `Uncle` first (`index/blocks.rs:421-433`); the driver reconciles the queue on every update including uncles (`driver.rs:243-249`), so 11 -> 10 -> 11' is always observed.
- R12 **An intermittent nonce-RPC failure in `update_block_status` leaves inconsistent state.** `block_status` is stored before any RPC (`tx/mod.rs:151-153`); the skipped mark/resubmit is redone on the next advancing block; `queue()` still submits fresh actions (`137-139`). Conservative only.
- R13 **`nonce()` falling back to the `latest` tag when `block_status` is `None`.** Dead branch: `queue()` guards on `block_status` (`tx/mod.rs:137`) and `update_block_status` sets it before calling `nonce()` (`153`, `188`).
- R14 **`executed_at` earlier than the true inclusion block.** In an honest view the reading at `latest` reflects inclusion `<= latest`, so `executed_at = latest` is an upper bound and `unmark_executed(latest+1)` on a real uncle is conservative (`tx/mod.rs:174-178, 189-194`).
- R15 **Prune removes a row a later unmark needs.** Prune is at `safe`, unmark at `>= safe + 1` (`tx/mod.rs:162-164, 170`), and the watcher never regresses below `safe` without a fatal `ExceededMaxReorgDepth` (`index/blocks.rs:435-439`).
- R16 **Panics reachable from untrusted input in `tx/`.** None found: `expect("valid regex")` on a static literal (`tx/mod.rs:354`); `as u128` casts saturate (`tx/fees.rs:16`); all `i64`/`usize` conversions are `try_from` -> `Error::Overflow` (`tx/storage.rs:314-318`); regex over node-controlled `payload.message` is linear-time; no indexing or slicing.
- R17 **Signer key leakage through `Debug`, logs or serialisation.** `Signer`'s `Debug` prints the address only (`tx/signer.rs:96-100`); raw key copies are zeroized after use (`60-63`, `89-92`); `SignedTransaction` and `TransactionQueue` have no `Debug`; warn logs carry nonce and RPC error only.
- R18 **"already known" (identical resend after a lost response) unrecognised.** Falls in the generic branch (`tx/mod.rs:287-293`) and repeats only while the fresh estimate is byte-identical; the pooled original mines regardless. Noise, not a defect.
- R19 **In-flight cap bypass via resubmission.** Resubmits reuse rows (`tx/mod.rs:224-237`); the cap is on allocation (`205-206`) by design.
- R20 **`eth_feeHistory` unsupported by the node breaks fee estimation permanently.** alloy falls back to the latest block's base fee (`alloy-provider-2.0.5/src/provider/trait.rs:288-303`); a hard error is `Rpc` and therefore intermittent.
- R21 **SQLite work blocks the tokio runtime.** sqlx's SQLite driver runs each connection on a dedicated worker thread (crate-level knowledge; not traced line-by-line this session); not pursued.

## 5. Observations (plausible, unproven; not filed)

- O1 (30%) `database is locked` is fatal. sqlx sets no `journal_mode` by default (`sqlx-sqlite-0.9.0/src/options/mod.rs:179-183`), so the file runs in SQLite's default rollback-journal mode unless the URL says otherwise (the sample URLs do not: `*.sample.toml:21`); `busy_timeout` is 5 s (`:203`); the pool allows 10 connections (`sqlx-core-0.9.0/src/pool/options.rs:151`). The validator's `SecretStore` shares the pool from effect tasks (`crates/validator/src/service/mod.rs:46-50`, `service/effect.rs:126, 265`). A reader or writer holding a lock for > 5 s turns into a `Storage` error, which `is_intermittent` classifies fatal (`tx/mod.rs:47-54`). Whether any secret-store transaction can hold a lock that long is R5's territory.
- O2 (35%) Ordering: the snapshot is committed (`state/mod.rs:239`) before the actions of that update are enqueued (`driver.rs:283`). Steady state is at-least-once via the restart replay from `safe`, but after a pruned warp only one snapshot may remain (`state/storage.rs:86-101` MIN/MAX; `index/blocks.rs:257-266` "no synthetic reorg"), and with `max_reorg_depth = 0` `safe == latest`; in both, a crash in that window loses the actions permanently. R2 boundary (driver/state); noted for the shared Critic.
- O3 (30%) Nethermind's replacement-rejection wording (believed `ReplacementNotAllowed`) is not matched by `is_transaction_underpriced` (`tx/mod.rs:362-368`); consequence is slower convergence since the pooled transaction still exists. Not verifiable offline.
- O4 (40%) Fee estimates and nonce readings are trusted absolutely (A4). With the default `priority_fee_cap_percentage = None` an inflated `reward` percentile from the RPC is paid; the ratio cap cannot defend against an inflated base fee either. Folded into F2-CORE-060's remediation (absolute ceiling).
- O5 (35%) Whether Nethermind block producers on Gnosis include zero-tip transactions (`MinGasPrice` default 1 wei) is unverified; it decides whether F2-CORE-062's stall also applies through Nethermind RPCs.
- O6 (25%) Queued rows are uncapped; with the queue stalled, `expires_at: None` actions accumulate without bound (bounded in practice by the services' emission rate).
- O7 (15%) `cap_priority_fee` with `max_priority_fee_per_gas > max_fee_per_gas` returns `max_fee_per_gas = 0` (`tx/fees.rs:21-30`); unreachable with alloy's estimator (`mf = 2 * base + tip`, `alloy-provider-2.0.5/src/utils.rs:119-123`).
- O8 (20%) `SigningError` discards the alloy error cause (`tx/signer.rs:41-45`); diagnostics only.
- O9 (10%) `tracing::warn!(?err)` prints node-controlled error text (`tx/mod.rs:272-276, 288-292`); no secret content identified.
- O10 (15%) The configuration string holding the signer key is not zeroized before `B256::deserialize` (`tx/signer.rs:84-94`); inherent to file-based config, R6/R7's config files.
- O11 (40%) Every restart re-checks and resubmits (with a 10% bump) every in-flight row older than `blocks_before_resubmit` (`tx/mod.rs:167-171, 195`); expected, but each restart costs one bump per in-flight row. Context for F2-CORE-060.

## 6. Answers to the assignment's questions (summary)

- Write ordering: allocate (commit) -> fees -> sign -> broadcast -> record (commit). Safe in both directions for the queue itself (R5, R6). Enqueue is committed before submission (`tx/mod.rs:136-139`), so intermittent submit failures lose nothing.
- Nonce never released: correct, by design; blocking consequence in F2-CORE-064.
- Two live rows one nonce: impossible (R3).
- Execution inference: account nonce only, at `BlockId::Number(latest)`; no receipts, no hashes; marks monotonic; regression handled via `unmark_executed(latest+1)` (F2-CORE-061).
- `expires_at` after allocation: ignored (F2-CORE-064).
- Fee bump: unbounded geometric, floor monotonic, ratio cap preserved but no absolute cap (F2-CORE-060); underpriced-replacement rejections advance the floor (`tx/mod.rs:271-283`), first-submission underpriced rejections and all other errors do not (F2-CORE-062).
- Row binding to chain/signer: none (F2-CORE-066).
- Config validation: none beyond serde (F2-CORE-065).
- At-least-once replay: the queue re-enqueues and re-broadcasts duplicates; no dedup (F2-CORE-063).
- sqlx features in force: `["sqlite", "runtime-tokio"]` (workspace `Cargo.toml:19`); pool `idle_timeout`/`max_lifetime` disabled (`utils.rs:56-62`); no pragmas set by core; SQLite defaults apply (O1).
