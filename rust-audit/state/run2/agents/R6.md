## Hypotheses considered and rejected (with the refuting citation)

1. **VAL-H10 — secrets printed by `warn!(?effect)` / `trace!(?resume)`.** Refuted. `Effect` carries `Arc<KeyShare>`; `KeyShare(keys::KeyPackage)` derives `Debug` (`frost/keygen.rs:433-435`) and `KeyPackage` derives `Debug` (`frost-core-3.0.0/src/keys.rs:631`) but its `SigningShare` field has a redacting impl (`keys.rs:126-133`: `f.debug_tuple("SigningShare").field(&"<redacted>")`). `Resume::Setup{secrets}` → `Secrets` derives `Debug` (`frost/keygen.rs:27-32`) over `EncryptionKey` (redacted, `frost/ecdh.rs:50-54`), `round1::SecretPackage` (coefficients redacted, `keys/dkg.rs:191-199`) and a public PoK. `Resume::Nonce{nonces}` → `Nonces` has a redacting impl (`frost/preprocess.rs:64-71`). `round2::SecretPackage` also redacts (`keys/dkg.rs:337-345`). `InternalError(String)` is built from `Display` of `frost::error::Error` (culprit address + frost error, `frost/error.rs:10-20`), store errors (sqlx/serde messages, `store.rs:63-74`) and nonces errors (`nonces.rs:224-231`) — none carry secret bytes. Nothing `Debug`-prints `State` or `Config` (grep `?state`, `?config`: no hits outside tests).
2. **Unknown config fields silently accepted because `deny_unknown_fields` is combined with `flatten` (checklist 8).** Refuted by execution (scratch crate, same serde/toml versions): unknown top-level key, misspelled `[observabilty]`, unknown key inside `[index]`, unknown `[indexer]` table all error. Cosmetic: the reported span is `0..0` (line 1) for the flattened cases.
3. **Selector / `topic0` mismatch between `bindings.rs` and the contracts.** Refuted by execution (see commands): all 17 events and 18 functions match the compiled artifacts; indexed parameters match.
4. **`OracleResult` accepted from the wrong oracle.** Refuted: `handle_oracle_result` receives `log.address` (`state/mod.rs:458-460`) and requires `expected == oracle` in both arms (`state/sign.rs:180-189, 222-227`).
5. **VAL-H7 — `ReconcileGroupSecrets` computed from pre-log state deletes secrets written by the same block's effects.** Largely refuted by the pruning redesign: reconciliation only _schedules_ deletion (`store.rs:311-350`), collection happens at `housekeeping` for schedules `<= safe` (`effect.rs:278-308`, `store.rs:356-374`), a group that reappears has its schedule cancelled (`schedule_absent_groups`, `store.rs:381-412`; `store_keygen_secrets` clears it, `store.rs:183-192`), and outdated reconciliations are ignored by block (`store.rs:322-333`). The residual window (a schedule at block N collected at `safe >= N` before a same-block re-retain commits) requires the group to be absent for `max_reorg_depth` blocks and then reappear on a _replay_, which the handbook documents as accepted behaviour (`docs/validator-handbook.md:92`). No deterministic trigger found → observation O3.
6. **`Config`/`Signer` leak through the tracing path.** Refuted: `main.rs:43` logs only the file path; `Signer`'s `Debug` prints the address (`core/tx/signer.rs:96-100`); the raw-document leak is the separate `Box<dyn Error>` path (F2-VAL-060).
7. **Coordinator address can change under the validator at runtime.** Refuted: `Consensus._COORDINATOR` is `immutable` (`contracts/src/Consensus.sol:60, 119-121`); resolving once at startup (`main.rs:49-52`) is sound.
8. **Effects other than `KeyGenSetup`/`NonceTree` strand state on failure.** Refuted per effect: `StartNonceGeneration` and `ReconcileGroupSecrets` are re-emitted every `NewBlock` (`state/mod.rs:468-470`, `keygen.rs:1352` for the eager start); `RevealNonceCommitments` and `UseNonce` failures leave a session that the protocol timeouts restart (`state/sign.rs:515-560`), and `take_nonce` is a single `DELETE … RETURNING` so a failure never burns a nonce without a resume (`store.rs:281-296`).
9. **Reverting transactions block the queue (fixed gas too low → stuck nonce).** Refuted: an included-but-reverted transaction still consumes the nonce and is marked executed by nonce (`tx/mod.rs:176-186`); expiry applies only before nonce allocation (`tx/storage.rs:150-155`), so no head-of-line blocking.
10. **Undecodable `Operation` (enum ≥ 2) in `TransactionProposed` from the Consensus contract.** Refuted for the protocol contract: Solidity cannot emit an out-of-range enum. The same decode failure _from an allow-listed oracle address_ is real and is scenario 3 of F2-VAL-061.
11. **Empty `participants` accepted.** Refuted: `participants_set` returns `None` below `min_participants` (floor 2, `consensus/group.rs:212-233`) and `ValidatorService::new` fails with `InvalidValidators` (`service/mod.rs:51-57`).

## Observations (plausible, unproven; not filed)

- **O1 — Fixed gas limits unverified (checklist 11).** `signShareWithCallback` = 400 000 (`action.rs:276-299`) covers share verification, Merkle proofs, aggregation on the last share, and the `stageEpoch`/`attestTransaction` callback (`Consensus.sol:229-247, 272-286`); `keyGenAndCommit` = 250 000 does not scale with `threshold` (the contract stores only `q`-nonzero check, `c.length`, `register`, `state`, `key = add(key, c[0])`, `FROSTCoordinator.sol:371-389`), so it is plausibly safe. No gas snapshot exists in-tree and `forge` cannot compile offline (no cached solc), so nothing could be measured. An under-provisioned constant is an included-and-reverted transaction = silent non-participation. Suggest QA run the contracts' tests with `--gas-report` for `n = 6..20`. Certainty of a real problem: ~25%.
- **O2 — `Action::Preprocess` and `Action::SetValidatorStaker` never expire (`action.rs:252-254, 368-378`).** `SetValidatorStaker` is re-queued on every start while `getValidatorStaker != staker` (`main.rs:82-93`); a restart before the first one is mined queues a duplicate (harmless extra ~26k gas). ~60% that duplicates occur in practice; impact negligible.
- **O3 — Restart-replay vs. housekeeping race** (see rejected 5): `housekeeping(status)` runs inline right after the `NewBlock` commands are spawned (`driver.rs:292-294`), concurrently with the reconcile task's cancellation transaction; the handbook documents the acceptable outcome. ~20%.
- **O4 — `oracles` defaults to empty** (`config.rs:68-69`); a validator then ignores every proposal with only a `debug!` (`transactions.rs:32-40`) and no startup warning. Operational; ~Informational.
- **O5 — Sample `signer` is the well-known key `0x…01`** (`validator.sample.toml:15`, address `0x7E5F…5Bdf`); no guard rejects well-known/test keys or the zero key. Informational hardening.
- **O6 — `genesis_salt` zero → context `B256::ZERO`** (`consensus/group.rs:288-297`) so identical participant sets on two deployments share a genesis group id; consistency is with deployment tooling (the Beta network uses `0x5afe…`, `docs/configuration.md:29-30`). Informational.
- **O7 — Injected `KeyGenCommitted` from non-members** (a valid PoK suffices, `keygen.rs:171-175`) inflates `commitments.len()` past `count` so the round never closes; reachable only under F2-VAL-061's precondition; noted there.
- **O8 — Cross-cutting notes for R7/R8:** the `Box<dyn Error>` config leak (F2-VAL-060), the `--config-file=` documentation (F2-VAL-064), the missing `?mode=rwc`, the root runtime image and the exit-status behaviour all recur in `crates/sentinel` (`crates/sentinel/src/main.rs`, `sentinel.sample.toml:4`, `docs/sentinel-handbook.md:76`, `crates/sentinel/Dockerfile`).
- **O9 — `EventLog` decode failure is fatal for the batch** (`events.rs:491-510`) — beyond the oracle case, a protocol-contract upgrade that changes an event's ABI would wedge every validator at that block until a binary upgrade; by design, but worth a `fallible_events`-style escape hatch for decode errors.
- **O10 — `handle_sign` injection via legitimate `Coordinator.sign` spam** (VAL-H6, R5) interacts with F2-VAL-062: cheap sequence burning makes threshold crossings, and therefore restart-time races, frequent.
