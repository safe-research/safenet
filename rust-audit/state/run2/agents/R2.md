## 4. Housekeeping diff audit (`driver.rs` +16, `effects.rs` +49, PR #907)

No defect in the wiring itself. What the new path does and how it was assessed:

- Runs only for `Update::Block(BlockUpdate::New)` (`driver.rs:257-260`), after `handle_update`, `prune`, action encoding and `transactions.queue` (`driver.rs:261-294`), so actions produced by the block are durable before maintenance starts. Skipped for `Uncle`, `Warp`, `Logs` and resumes; during a long warp no housekeeping runs until the first `New` (bounded, acceptable).
- Uses `block_status` captured before `handle_update` (`driver.rs:242`) - the same value `prune` uses (`driver.rs:263`), matching the module doc ("with the same chain view it prunes state snapshots to", `driver.rs:9-10`). With `max_reorg_depth >= 1` the oldest retained snapshot equals `status.safe` (`storage.rs:152-159`; eviction `blocks.rs:453-462`), so anything a restart could roll back to is at or above the housekeeping boundary. See O13 for `max_reorg_depth = 0`.
- Failure handling: the trait method returns `()` (`effects.rs:28-32`); the validator implementation catches every error, logs at `warn`, increments `housekeeping_total{failure}` and relies on the next block to retry (`crates/validator/src/service/effect.rs:278-308`). Nothing can poison the driver from here.
- Latency and locking: one SQLite transaction with two `DELETE ... WHERE delete_at_block <= ?` statements (`crates/validator/src/secrets/store.rs:356-375`), awaited inline on the driver task; no index is visible on `delete_at_block` (R5), but the tables are small. The await is unbounded by construction - folded into F2-CORE-034. Runs on the same pool as concurrent effect tasks; see O1 for journal-mode contention.
- Concurrency: `EffectManager::housekeeping` takes `&self` and shares the `Arc<Handler>` with running effect tasks (`effects.rs:72-74`); serialisation of shared handler state is the handler's job (validator: `Semaphore`/`Mutex` in `secrets/nonces.rs`).
- Tests added by the PR (`effects.rs:159-183`) cover forwarding and the `Pure` default only; no test covers ordering relative to `prune`/`queue` (test gap, informational).

## 6. Hypotheses considered and rejected (with the refuting citation)

1. **Core's `trace!(?resume)` / `trace!(?effect)` lines leak DKG secrets or nonces** (`driver.rs:240, 267`; `effects.rs:62, 66, 90`; the shipped test config enables `safenet_core=trace`, `scripts/lib/shared_test_scripts.sh:156`). Refuted at the pinned versions: every secret-bearing type redacts `Debug` - `EncryptionKey` (`crates/validator/src/frost/ecdh.rs:50-52`, `"redacted"`), frost `round1::SecretPackage` (`frost-core-3.0.0/src/keys/dkg.rs:191-204`, `coefficients: "<redacted>"`), `SigningNonces` (`round1.rs:271-279`), `SigningShare` inside `KeyShare(KeyPackage)` (`keys.rs:126-133`; `crates/validator/src/frost/keygen.rs:433-435`), validator `Nonces` (`crates/validator/src/frost/preprocess.rs:64-70`). `Resume::NonceCommitments` carries public commitments only. Residual design risk recorded as O7.
2. **`utils::Json` prints secrets** - it is used only for JSON-RPC request/response tracing (`crates/core/src/provider/mod.rs:51-52, 87`); payloads are chain data and signed raw transactions, no key material.
3. **Poisoned state machine after a failed transition causes silent misbehaviour** - `inner` is left `None` only after an error (`state/mod.rs:171, 252`) and the driver exits on the first error (`driver.rs:195-198`); a second call never happens. Fail-stop, not corruption.
4. **`prune` can delete a snapshot a later `Uncle` needs** - prune keeps `>= safe` plus the newest row (`storage.rs:152-159`); the watcher's `safe` only moves by eviction (`blocks.rs:453-462`) and the driver prunes with that same status (`driver.rs:263`); restart uncles are emitted at `safe + 1` with `safe = MIN(snapshots)` (`blocks.rs:261-266`, `storage.rs:86-101`). A node that is behind the persisted range is R1's (fail-stop `BadUpdate`, `state/mod.rs:190-199, 240`).
5. **A transition panic under the tokio `Mutex` leaves a usable but inconsistent machine** - a panic on the main task aborts the process (`#[tokio::main]`), tokio's `Mutex` does not poison, and the machine is never used again.
6. **The `Mutex` across awaits in `handle_update`/`handle_resume` is a lock hazard** - both take `&mut self` (`state/mod.rs:166-170, 250-252`); the lock is redundant, not shared.
7. **`is_next_in_range` accepts inverted or out-of-range log batches** - `BlockEvents` requires `start == last == latest`; `WarpEvents` requires `start == range.start` and `last` inside the range; each log is checked for `blocks.contains` and strict `(block, index)` ordering (`state/mod.rs:200-211, 278-281`).
8. **`Uncle` during `WarpEvents` corrupts state** - the guard rejects it with `BadUpdate` (`state/mod.rs:182-185, 240`); the watcher does not emit it (R1).
9. **`EffectManager::next` loses a resume when the driver's `select!` picks the watcher branch** - `JoinSet::join_next` is cancel-safe and the crate tests it (`effects.rs:81-85, 212-226`).
10. **Dropping the driver on shutdown leaves effects running** - the `JoinSet` aborts on drop (`effects.rs:35-38`); in-flight effects are consumptive-safe by contract (`effects.rs:22-25`).
11. **`shutdown_signal`'s `unwrap`s can panic in production** - signal registration fails only outside a runtime; `run` is awaited inside `#[tokio::main]` (`utils.rs:19-26`; `crates/validator/src/main.rs:32, 96`; `crates/sentinel/src/main.rs:29, 86`).
12. **`crate::metrics::initialize` spawns outside a runtime** - both binaries call `observability::init` inside `#[tokio::main]` (`metrics.rs:89`; `validator/main.rs:41`; `sentinel/main.rs:38`); the exporter also spawns onto the current runtime (`metrics-exporter-prometheus-0.18.3/src/exporter/builder.rs:456-465`).
13. **KDF misuse** - HKDF-SHA256, salt = non-empty domain, info = message parts (`kdf.rs:19-27`); the only production caller passes a constant 28-byte domain and a fixed 32-byte message (`crates/core/src/tx/signer.rs:59-64`; `crates/sentinel/src/hashing.rs:12-14, 51`); reference vector test passes (E1). Salt-normalisation and concatenation caveats recorded as O9.
14. **`serialization::from_str` mishandles input** - a pure `FromStr`/`Display` adapter over `Cow<str>` (`serialization.rs:19-33`); only config values flow through it (A1).
15. **Metric cursors misreport** - `Seen` is set to `to` when a `Warp` is received and `Processed` is restored to the persisted `latest` before the restart rollback (`driver.rs:139-143, 308-320`). Cosmetic; no decision depends on these gauges.
16. **`/health` keeps answering after `run` returns** - both `main`s return, the runtime drops and the listener with it (`validator/main.rs:96-98`; `sentinel/main.rs:86-88`); the status-code half is F2-CORE-031.
17. **Observability config exposes metrics publicly by default** - default `127.0.0.1:0` (`observability/mod.rs:29-35`); `deny_unknown_fields` set (`:17`). Operator overrides are R8's.
18. **`Driver::new` leaves partial state on failure** - only `CREATE TABLE IF NOT EXISTS` runs before `run` (`storage.rs:49-57`; `tx/storage.rs` per R3); `queue_action` before `run` only inserts because `block_status` is `None` (`tx/mod.rs:132-141`).
19. **Housekeeping deletes something the snapshot boundary still needs** - consistent for `max_reorg_depth >= 1` (section 4); the validator's own invariant ("only secrets scheduled at or before the snapshot boundary", `service/effect.rs:279-281`) is R5's to re-derive; depth 0 recorded as O13.
20. **`SnapshotStore::reorg` corrupts on a missing parent** - transactional; the `DELETE` is rolled back when the parent is absent (`storage.rs:127-143`; test `234-248`).
21. **`commit` per block leaks state through `serde_json` errors** - `Serialization` errors are fatal and carry no payload (`storage.rs:23-25`).
22. **`EffectHandler::housekeeping` default silently hides a missing implementation** - the default is an explicit no-op with a test (`effects.rs:28-32, 173-183`); only the validator overrides it, by design.
