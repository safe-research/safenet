## Claim

- The sample configuration is a valid, loadable config (the `parses_sample_config` test guarantees it) whose `signer` is the private key `0x…01` — the most widely known key on Ethereum — and whose `rpc` is live Gnosis mainnet. An operator who copies the sample and fixes only the addresses runs a mainnet sentinel whose gas and bonds anyone can sweep. A placeholder that fails validation (or an empty string) would fail loudly like the other deployment-specific fields are designed to.
- `Config::load` reads the whole TOML into a `String` that is dropped without zeroisation; the `Signer` deserializer takes care to zeroise its 32-byte copy, so the surviving plaintext is the config buffer.
- `voting_window` is documented (schema and sample) as the lifetime of a `Preparing` request; no such state exists — it bounds `WaitingForEngineCheck`/`WaitingForRequest` and sizes the engine timeout.
- The Dockerfile builds from the floating `rust:1-slim` tag (non-reproducible toolchain) and the runtime stage sets no non-root `USER`.

## Trigger

Operator copies the sample, sets `oracle`/`consensus`/`fee_token`, forgets `signer`, funds the account for gas and bonds. Funds are swept by anyone monitoring the well-known address.

## Considered and rejected

- "Operators are trusted (A1)": this is a footgun, not an attack; filed as Informational for the record. R8 covers the cross-crate Dockerfile and sample-config sweep; this entry records the sentinel-specific text.

## Remediation options

1. Ship an invalid placeholder for `signer` (e.g. `"<32-byte hex private key>"`) and keep the parse test on a fixture instead of the sample, or gate the sample test to accept a documented placeholder.
2. Read the config into `Zeroizing<String>`.
3. Fix the `voting_window` docs; pin `rust:1.<minor>-slim`; add a non-root `USER`.
