## Claim

`Driver::run` returns `()` after logging "unrecoverable watcher error; exiting" (`ExceededMaxReorgDepth`) or "unrecoverable driver error; exiting" (state-machine `Poisoned`/`BadUpdate`/`EndOfChain`, non-intermittent transaction-storage errors), and `main` then returns `Ok(())`, so the process exit status is 0. Container runtimes and supervisors configured with `restart: on-failure` / `Restart=on-failure` treat that as a clean stop and do not restart, and alerting keyed on non-zero exits stays silent. Conversely, while the process is alive the Prometheus listener's `/health` returns a constant `OK`, including when the driver is retrying a deterministic watcher error every 100 ms, when the rollover machine is `Halted`, or when the RPC has been unreachable for hours - so a liveness probe cannot distinguish a working validator from a wedged one. The validator-specific part is `main.rs`, which is the only place that can translate the driver's outcome into an exit status.

## Trigger

- Exit 0: a node serving out-of-order logs once makes `handle_update` return `Error::BadUpdate` (crates/core/src/state/mod.rs:207-211, 240); the driver logs and breaks; the container exits 0 and, under `restart: on-failure`, stays down. Same for a reorg deeper than `max_reorg_depth`, where the intended outcome ("fail loudly") is visible only in logs.
- Health: point the RPC at an unreachable host; the driver warns every 100 ms while `curl /health` returns `OK`.

Not executed this session (requires a chain or an RPC stub); the paths are unconditional in the cited code.

## Considered and rejected

- Is exit 0 intentional for the deep-reorg case? The commit message for PR #834 (per the codebase map) says the process should end; nothing says with status 0, and the test in row 6 would pass with either status.
- Restart policies of `always` mask the exit-status half but not the health half; Kubernetes liveness probes against `/health` would never fire during a stall.
- This overlaps the cross-crate lead CORE-H3 (R2, `driver.rs`); the validator-side remediation below is independent of any core change.

## Remediation options

1. Have `Driver::run` return `Result<(), Error>` (or an exit-reason enum) and let `main` return `Err` / call `std::process::exit(1)` on an unrecoverable stop; keep 0 for the shutdown signal. Two-line change in each service once core exposes the outcome.
2. Make `/health` meaningful: gate it on a shared `AtomicBool`/watch channel that the driver flips when it enters a retry loop longer than N seconds, when the state machine is `Halted`, or when `block_number{status="processed"}` stops advancing; document a `livenessProbe` and a `restart: always` recommendation in the handbook.

Tests to add: a driver test asserting a `BadUpdate` surfaces as an error from `run`; a binary-level test asserting non-zero exit on a forced watcher failure. No code is committed.
