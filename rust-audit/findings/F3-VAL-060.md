## Claim

The sample sets `database = "sqlite:/var/lib/safenet/validator/data/storage.db"` with no `mode` parameter. sqlx-sqlite 0.9.0 parses that with `create_if_missing: false`, and `connect_sqlite` does not change it, so a validator started from the sample with an empty data volume, as the handbook's `docker run` example sets up, exits at startup with `SqliteError { code: 14, message: "unable to open database file" }`. Every Aegis node starts with no database, so every operator who copies the sample hits this on the first start, and the SQLite message points at permissions or paths rather than at the missing `?mode=rwc`. The integration scripts append `?mode=rwc` and the devnet uses `sqlite::memory:`, so no test starts from the sample's URL shape. The sentinel sample has the same line.

## Trigger

An operator follows `docs/validator-handbook.md:116-129`: copies `validator.sample.toml`, fills in `rpc`, `signer`, `consensus` and the participants, keeps `database`, and runs the image with `--volume validator-data:/var/lib/safenet/validator/data`. The named volume is empty on a fresh Aegis node, so the first start ends with `Error: Database(SqliteError { code: 14, message: "unable to open database file" })` and exit status 1. Reproduced with the binary in row 6 (empty directory in place of the volume, loopback stub for `eth_chainId`).

## Considered and rejected

- A deliberate guard against a missing volume: the Dockerfile does not create `/var/lib/safenet/validator/data` (crates/validator/Dockerfile:24-37), so without a mount the parent directory is absent and SQLite fails even with `mode=rwc`. Creating the file inside an existing, mounted directory loses nothing, and neither the sample nor the handbook tells the operator to create the file first.
- Severity: the failure is loud, at startup, before any onchain action, and the fix is one config edit, so Low rather than Medium.
- Run 2 commit `fe9e84c`: the sample had the same line (`git show fe9e84c:crates/validator/validator.sample.toml`, line 21) and `connect_sqlite` is unchanged, so this is pre-existing.

## Remediation options

1. Append `?mode=rwc` to the `database` value in both samples and in the handbook text. Keeps the loud failure when the volume is not mounted (the directory does not exist in the image).
2. Set `create_if_missing(true)` in `connect_sqlite` for file databases. Fixes every config shape, including ones that drop the query string when an operator rewrites it.
3. Keep the default but wrap the startup error with a hint ("database file does not exist; append `?mode=rwc` to create it").

Tests to add: a startup test (or a `parses_sample_config` extension) that opens the sample's `database` with the path redirected into an empty temporary directory.

One correction to "Considered and rejected": "Creating the file inside an existing, mounted directory loses nothing" does not hold for a mistyped named volume. Docker creates a new, empty volume and mounts it, so the directory exists and `mode=rwc` would start the validator from an empty database, without the key share and DKG secrets kept in the right volume (`docs/validator-handbook.md:87`). Today's default refuses that start. See the remediation note in F3-XC-005.
