## Claim

The CLI is parsed with `argh` 0.1.19, which accepts `--config-file <path>` but not `--config-file=<path>`. The sample configuration header, the Dockerfile's `ENTRYPOINT` rationale and the handbook's `docker run` example all use the `=` form, so an operator following the documentation gets `Unrecognized argument: --config-file=validator.toml` and exit status 1. Executed this session against the audited binary. Not a security defect, but the primary operator path fails, and the failure message does not hint at the fix.

## Trigger

Run the image as documented: `docker run ... ghcr.io/safe-research/safenet-validator:main --config-file=validator.toml`. The container exits 1 with `Unrecognized argument`.

## Considered and rejected

- Newer `argh` versions: the pinned 0.1.19 does not accept `--key=value` (executed, row 2); no feature flag changes this.
- The same wording appears in `crates/sentinel/sentinel.sample.toml:4` and `docs/sentinel-handbook.md:76` (outside R6 scope; noted for R7/R8).

## Remediation options

1. Fix the three documents to `--config-file /path/...` (and the `args:` example to two list items). Zero code change.
2. Switch to a parser that accepts both forms (e.g. `clap` with `derive`), keeping `--version`. Adds a dependency.

Tests to add: none required; a doc-lint step that greps for `--config-file=` would prevent regressions. No code is committed.
