## Claim

`database` is parsed straight into `sqlx::sqlite::SqliteConnectOptions` with `FromStr`. In sqlx-sqlite 0.9.0 (pinned) `create_if_missing` defaults to `false` and is only enabled by the `mode=rwc` query parameter. The sample ships `database = "sqlite:/var/lib/safenet/validator/data/storage.db"`, and the handbook mounts an empty named volume at that directory, so the very first start opens a non-existent file read-write without create and fails with SQLite's "unable to open database file" - after the RPC connection has already been made (`Provider::connect` runs before `connect_sqlite`). The repository's own integration scripts append `?mode=rwc`, which is why CI never hits it. Operators will work around it by touching the file or adding the parameter, but the worked example the handbook tells them to copy does not run as shipped.

## Trigger

Fresh host: `cp validator.sample.toml validator.toml`, fill in `rpc`, `signer`, `consensus`, `participants`; `docker run` per the handbook with a new `validator-data` volume. The process connects to the RPC, then `connect_sqlite` fails (`unable to open database file`) and the container exits 1. Not executed this session (the step is only reachable after a live RPC connection, which run-2 rules forbid); rows 3-4 are the dependency's source at the pinned version.

## Considered and rejected

- Does `connect_sqlite` set `create_if_missing(true)`? No: `utils.rs:56-61` only disables recycling and calls `connect_with(options)` unchanged.
- Does the `parses_sample_config` test cover it? It only parses the TOML (`config.rs:282-289`); it never opens the database.
- Is `mode=rwc` in the handbook text? No occurrence in `docs/validator-handbook.md` (grep this session).

## Remediation options

1. Change the sample to `database = "sqlite:/var/lib/safenet/validator/data/storage.db?mode=rwc"` and mention the parameter in the handbook. Zero code change.
2. Call `.create_if_missing(true)` in `connect_sqlite` (or in the validator's `main`) so file-backed databases are created by default; document that an existing file is still required for read-only setups.

Tests to add: an integration-level smoke test that starts the binary against a temporary directory with the sample's `database` shape. No code is committed.
