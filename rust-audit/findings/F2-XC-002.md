## Claim

`database` is parsed into `sqlx::sqlite::SqliteConnectOptions` via `FromStr` and opened by `utils::connect_sqlite` without further options. sqlx 0.9 defaults to `create_if_missing = false`, and only the `?mode=rwc` URL parameter turns it on. The shipped samples use `sqlite:/var/lib/safenet/<service>/data/storage.db` with no `mode` parameter, and the handbooks' run commands mount an empty named volume at that directory. On a first start the file does not exist, SQLite is opened without `SQLITE_OPEN_CREATE`, and the service exits with `unable to open database file` after the RPC connection has already succeeded.

The impact is operability rather than security on its own, but the failure pushes operators toward two bad workarounds: pre-creating the file by hand inside a root-owned volume (see F2-XC-003), or switching to `sqlite::memory:`, which is the only form that appears anywhere in the repository's scripts and which silently discards every DKG secret and nonce chunk on restart (the handbook's own warning: loss of these secrets forgoes participation for an epoch, `docs/validator-handbook.md:75`). Nothing in CI exercises a file-backed database, so the documented deployment path is untested.

## Trigger

Copy a sample, fill in the deployment values, run the documented `docker run` with a new named volume. The E1 run reproduced the path with a loopback JSON-RPC stub (`http://127.0.0.1:8745`, started and stopped by R8) answering `eth_chainId`, so that `main` reached `connect_sqlite`.

## Considered and rejected

- "sqlx creates the file for `sqlite:` URLs": refuted by claim 5 and by the E1 run (no file after exit).
- "The volume ships a file": a Docker named volume is created empty; only the directory exists (the E1 mirrored this: directory present, file absent).
- "The error is obvious enough": it appears after a successful RPC handshake and looks like a permissions problem; nothing points at `mode=rwc`, which is not mentioned in the samples, the handbooks or `config.rs`.

## Remediation options

1. Call `.create_if_missing(true)` on the options inside `connect_sqlite` (one line; matches operator expectation for a service-owned file). Trade-off: a typo in the path silently creates an empty database elsewhere, so pair it with a startup log line stating the resolved filename.
2. Keep the default and document `?mode=rwc` in both samples and handbooks, with a note that `sqlite::memory:` must never be used for the validator.
3. Either way, add a file-backed database to at least one integration script so CI exercises the documented path.

Tests to add: an integration run with a file path in a fresh temporary directory.
