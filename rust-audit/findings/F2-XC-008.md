## Claim

Configuration loading is type-checked only; there is no semantic validation step. Three consequences:

1. Both samples set `signer` to the private key `1`. Its address, `0x7E5F4552091A69125d5DfCb7b8C2659029395Bdf`, is asserted by the validator's own test suite, and anyone can sign for it. A copy of the sample that misses this line starts normally, registers or bonds under a key the whole world holds, and any funds sent to that account are lost. Nothing rejects well-known keys (`1`, the Anvil/Hardhat defaults) at startup.
2. Both samples set `rpc` to `https://rpc.gnosischain.com`, the live Gnosis mainnet, while every contract address is the zero address. A half-edited sample therefore talks to production: the validator calls `getCoordinator()` on address zero and exits with an ABI error (a loud failure), but the sentinel, whose `oracle`/`consensus`/`fee_token` are zero, starts, indexes mainnet and idles forever without ever seeing an event (a silent one). The zero-address defaults are a recorded TODO (`config.rs:44-48`; map Section 4 known item), hence the `known` tag.
3. No cross-field checks: `voting_window` is a plain `u64`, so `0` is accepted and yields the 1-second floor for the engine timeout and immediate request cleanup; `genesis_salt` defaults to all zeros; `participants` may be empty; nothing checks that `signer` is among `participants` for a validator.

Handbooks do instruct operators to edit the samples (`docs/validator-handbook.md:96-101`, `docs/sentinel-handbook.md:61-66`), so this is Informational hardening.

## Trigger

An operator copies a sample and misses one of the placeholder lines; the E1 config runs in `state/run2/logs/r8-config-tests.txt` show that such files parse (the control run proceeded to the RPC step).

## Considered and rejected

- Treating this as a vulnerability: the operator is trusted (A1) and documentation covers the intent; the value here is a cheap guard rail.
- `deny_unknown_fields` weaknesses: tested and refuted (E1, same log): unknown keys are rejected at top level, in the flattened driver tables and inside `[index]`.

## Remediation options

1. Add `Config::validate(&self)` called from `load`: reject the zero address for every contract field, reject a small set of well-known private keys, require `voting_window >= 1` (or type it `NonZeroU64`), warn when `genesis_salt` is zero or `participants` is empty, and for the validator warn when `signer` is not among `participants`.
2. Ship samples with `rpc = "http://localhost:8545"` (or an empty placeholder that fails parsing) so a half-edited file cannot reach mainnet, and replace `signer` with an obviously invalid placeholder such as `"<0x-prefixed 32-byte hex private key>"`.

Tests to add: config tests for each rejection.
