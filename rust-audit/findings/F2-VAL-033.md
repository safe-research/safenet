## Claim

`handle_sign_revealed_nonces` sets `last_signer = event.participant` on every accepted reveal, and `revealed.insert` overwrites. The coordinator's `signRevealNonces` only verifies the Merkle proof; it does not reject a second reveal from the same participant for the same signature id. A signer `M` that reveals once, waits for the other signers, and reveals again is `last_signer` in every honest validator's state. If the ceremony then times out in `CollectNonceCommitments` (because some other signer never revealed), the honest validators make `M` responsible for the restart and wait another `signing_timeout` (default 6 blocks, about 30 s) before removing `M` and having everyone sign. `M` is excluded only after that second timeout, so the cost is one extra timeout per ceremony per colluding signer, and each extra `WaitingForRequest` window is an additional opportunity for F2-VAL-032. Nothing about nonce reuse or binding factors is affected: a re-reveal at the same offset must present the same leaf, so `revealed[M]` is overwritten with identical commitments.

## Trigger

Signers `{A, B, M, X}` with threshold 3; `X` is offline. `M` reveals at block `t`, `A` and `B` reveal at `t+1`, `M` re-reveals the same leaf at `t+2` (`revealed.len() == 3 < 4`, so the state stays `CollectNonceCommitments`, `last_signer = M`). At the deadline `signers = {A, B, M}`, `responsible = M`; `M` never calls `sign`. Honest validators wait until `deadline + 6`, drop `M`, and only then all call `sign` with `{A, B}` - below threshold 3, so the ceremony dies entirely (with a larger group it continues one timeout late).

## Considered and rejected

- `revealed` cannot be changed to different commitments by a re-reveal: the leaf `keccak(offset, D, E)` is bound to the sequence's offset and the proof to the committed root, so a second valid reveal at the same `sid` is the same `(D, E)`.
- Once `revealed.len() == signers.len()` the state advances and further reveals are ignored (sign.rs:346-349), so the trick only works while at least one signer is missing.

## Remediation options

1. Only update `last_signer` when `revealed.insert(..)` returns `None` (first reveal from that participant).
2. Choose the responsible party deterministically among revealers (e.g. lowest address), which also removes the dependence on log ordering.

Tests to add: transition test with a duplicate reveal asserting `last_signer` is unchanged. No code is committed.
