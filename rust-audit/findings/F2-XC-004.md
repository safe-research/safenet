## Trigger

For h2: an operator sets `metrics_address` to a non-loopback address and a network peer opens HTTP/2 to it. Everything else: none identified.

## Considered and rejected

- Repeating the advisories' CVSS as severity: rejected per the brief; the 7.5 item is not compiled.
- `ruint` via alloy's ABI decoding of chain data: decoding uses byte conversions, not the affected shift functions; formatting (`to_base_be`) only loops on no-alloc builds.
- `event-listener`/`lru`: both require API usage patterns (`with_tag` with `!Send`, `catch_unwind` around a panicking `Drop`) absent from sqlx and alloy-provider.
- h2 on the client side (RPC over `https`, sentinel→engine): rejected because reqwest is compiled without its `http2` feature (claim 3b); the workspace pins `reqwest = { default-features = false, features = ["json", "rustls"] }` (`Cargo.toml:15`) and alloy's reqwest dependencies are `default-features = false` as well, so HTTP/2 can never be negotiated by these binaries as clients.
- `--target all` for the lockfile-only crates could not be run offline (needs `android_system_properties`); their absence from the host graph is what matters for the shipped Linux images.

## Remediation options

1. `cargo update -p h2 -p rustls -p ruint -p crossbeam-epoch -p lru -p event-listener` (all patched releases are semver-compatible) and commit the lockfile.
2. Add `cargo audit` (or `cargo deny check advisories bans`) to `just check` with a reviewed ignore list, so the next advisory blocks a PR; add a `[workspace.metadata]`/`deny.toml` banning duplicate `rand`/`digest` majors once upstream allows.
3. Trim features: replace `alloy` `full` with the providers/contract/signer-local/rpc-types subset that compiles, and set `metrics-exporter-prometheus = { default-features = false, features = ["http-listener"] }`; this removes ws/ipc/pubsub, `c-kzg`/`blst` and the push-gateway client from the binaries.

Tests to add: none beyond the CI gate.
