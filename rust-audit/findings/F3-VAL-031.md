## Claim

A validator burns its nonce pair the moment it enters `CollectSigningShares`: when it processes the last signer's commitment, or at the commitment timeout. The timeout runs in the optimistic `NewBlock(deadline)` that the core applies right after block `deadline - 1`'s logs. Both decisions rest on the newest block, which is not final. If that block is orphaned and its replacement holds a different set of first commitments by the deadline, the honest validators that processed the orphaned block can only ever contribute to the first root R1 (their pairs are gone, and their R1 shares are rebroadcast onto the new branch). The others contribute to the second root R2.

At the share-round timeout the ceremony restarts only with the largest selection that reached the threshold. If none did, every validator drops it. With 5 validators and threshold 3, a 2 and 2 split of the honest shares drops the ceremony. So does a 3 and 2 split where the larger side counts a misbehaving member, who then stalls the restart. In both cases at least four honest validators were online. A dropped transaction ceremony cannot simply be re-proposed: the SentinelOracle refuses a second request with the same id, so the oracle data must change or the next epoch must start. A dropped rollover ceremony skips the epoch.

The documentation says the opposite: "Shallow reorgs of 1 block are not an issue" (`docs/overview.md:83`), and a reorged-out share leads to a restart under a new signature id (`docs/overview.md:68`). The code comment calling the canonical selection "necessarily unique" (`state/sign.rs:618-622`) also stops holding once honest shares are split and a member submits to both roots; the tie-break is still deterministic.

## Trigger

Aegis: 5 validators, threshold 3, `signing_timeout` 6, Gnosis 5 s blocks. Honest A, B, C, D and one misbehaving member M (within f < n/3). `Sign` at block s, commitment deadline d = s + 6.

1. A, B, C and D commit at s+1. M sends its commitment so that it lands in block d-1 and nowhere earlier, for example privately to the builder of that slot.
2. Block d-1 arrives late and is later orphaned. A and B, whose RPC nodes imported it, process it: M's commitment completes C1 = {A, B, C, D, M}, they enter `CollectSigningShares`, burn their pairs and broadcast shares for R1 = root(C1) (basis 3, `state/sign.rs:287-324`). C and D never see block d-1.
3. The replacement block at height d-1 does not contain M's commitment (M replaced its pending transaction, or it never reached the public mempool). After `Uncle(d-1)`, every validator reaches `NewBlock(d)` with C2 = {A, B, C, D} (4 of 5, at least 3) and continues (basis 1). A and B get `None` from the store and produce nothing. C and D produce shares for R2 = root(C2).
4. A's and B's R1 shares are rebroadcast by their queues and land. R1 = {A, B}, R2 = {C, D} (basis 4).
5. Share deadline: no selection reaches 3, so every validator drops the ceremony (basis 5). If M instead adds a valid R1 share last, R1 = {A, B, M} becomes canonical, C and D drop, and A, B and M wait with M responsible; M never calls `sign`, at the timeout M is removed, {A, B} is below 3 and the ceremony is dropped (basis 6). Either way the transaction is never attested and cannot be re-proposed with the same oracle data in this epoch (basis 8). A 3 and 1 or 1 and 3 split survives: the side with three honest shares restarts and completes.

All-honest variant: the orphaned block d-1 carries honest E's late commitment, the replacement lacks it, E did not process d-1, and exactly two of the other four did. R1 = 2, R2 = 2, nothing reaches 3, and the ceremony is dropped with five honest validators online. This is rarer: the replacement block is built a slot later and normally includes the transaction.

A misbehaving member alone cannot cause any of this: it needs a natural orphan of exactly block d-1, and exactly two of the four honest validators must have processed that block.

## Considered and rejected

- Without a reorg, every honest validator derives the same `committed` set (first valid commitment per signer) and the same root, so honest shares never split; fake roots hold only the attacker's shares, fewer than the threshold.
- If the replacement block carries the same commitments, or a missing commitment lands before the deadline, C2 equals C1 and there is one root. The split needs the change to straddle the deadline, so only block d-1 matters.
- If every honest validator processed the orphaned block, all honest shares are on R1, which completes on the new branch or restarts with them.
- The tie-break between equal selections is deterministic (`BTreeMap` order), so validators never disagree on the outcome; the defect is that the outcome is a drop.
- Pre-existing in part: at `fe9e84c` the all-committed path already burned the nonce on entering the share round (`handle_sign_revealed_nonces` emitted `Effect::UseNonce`) and used the same restart rule. The timeout path that continues and burns at once (#1008) and the optimistic `NewBlock(deadline)` (#1015) are new since run 2.

## Remediation options

1. When no selection reaches the threshold, or this validator is outside the chosen one, restart with every validator that committed for the old signature id instead of dropping. Pick the responsible party deterministically (for example the lowest address), or make everyone responsible. A restart gets a new signature id and fresh pairs, so this cannot reuse a nonce.
2. Keep the restart rule but count, for the restart set, every participant whose share landed on any root this validator computed. This needs the computed roots to survive a reorg, so they would live outside the snapshot.
3. Correct `docs/overview.md:68, 83` and the comment at `state/sign.rs:618-622` to state the split case.

Tests to add: a state-machine test that feeds two branches (orphaned block d-1 with the fifth commitment, replacement without it) to five `Transition` instances, three of which processed the orphan, and asserts that the ceremony is restarted rather than dropped.

Checks:

- In the construction above M can add shares only under roots whose leaves include it (`FROSTSignatureShares.sol:90`), so M is on R1 only, as written. The "necessarily unique" comment (`state/sign.rs:618-622`) fails only when a member belongs to both roots and signs both, which reuses that member's own nonce pair across two binding factors and leaks its own signing share; only a misbehaving member does that, and the tie-break stays deterministic (`BTreeMap` order, `max_by_key`).
- If every honest validator processed the orphan, all honest shares are on R1 and complete on the new branch, because `signShare` does not look at commitments (`FROSTCoordinator.sol:566-581`). The third "Considered and rejected" bullet is right.
- The documentation contradiction in row 7 can be fixed on its own (remediation 3).

## QA (QA3-VAL, 2026-10-08)

Result: Reproduced the impact rule (the share-round drop); the reorg trigger that produces the split is not executed (traced, as the Critic noted).

Route: a state-machine test drives the real `handle_sign_shared` (records shares per selection root) and the real `handle_signing_timeouts` (`CollectSigningShares` branch, basis 5) via `apply_transition`, at Aegis sizing (5 validators, threshold 3). This is the mechanism that turns a split into a dropped ceremony; the reorg origin of the split (an early nonce burn on a non-final block at the commitment deadline, plus split RPC views) is cited E2 in the finding and not driven here, which is why this stays a partial reproduction.

Hunks reverted, worktree clean.

Reason. Low stands. One-block orphans are routine on Gnosis (researcher consult: Dora 10 to 13 a day, 585 to 760 per million slots; beaconcha.in 4.35 a day; upper bounds for any one node), and most arrive late, so split validator views are realistic. What makes the split rare is the third condition: the replacement block normally carries the same commitments from the mempool, so the committed sets differ only when a commitment reached the orphan alone, which a misbehaving member can arrange for its own commitment but not for the orphan. The loss is one ceremony, recoverable by a new proposal.
