## Claim

#1046 made configuration parse errors drop the document: `ParseError::new` calls `inner.set_input(None)` and keeps only the position (`crates/core/src/config.rs:33-48`). Its doc says the error "never contains the contents of the configuration file, which holds secrets such as the signer's private key or an RPC URL with an API key, so it is safe to log" (`config.rs:22-25`).

The error still carries serde's message, and serde quotes the offending value. When the value in a typed field is the private key, the key is printed. A quoted string in an integer field gives `invalid type: string "0x<key>", expected a nonzero u64` (validator `blocks_per_epoch`, `key_gen_timeout`, `signing_timeout`, `oracle_timeout`, all `NonZeroU64`; `config.rs:63-73`) or `… expected u64` (sentinel `voting_window`, `crates/sentinel/src/config.rs:49`). A hex string in the sentinel's `engine` (a plain `Url`, `config.rs:51`) gives `relative URL without a base: "<key>"`. Both binaries return the error from `main`, which prints it to stderr (`main.rs:33-40` in each crate), and container logs pick it up. Fields parsed by key-safe code do not echo: an `Address` such as `fee_token` gives `invalid string length`, and the `signer` parser gives a key-free message (#1007).

This is a residual of F2-XC-001's class (configuration errors leaking the signer key). That row is Fixed by #1046 for the whole-document path; CA3-FIX recorded this narrower path as "not filed". It is not F3-XC-130, which covers the `rpc` field quoted through alloy's IPC fallback.

## Trigger

The operator pastes the private key into a typed numeric field (`blocks_per_epoch`, `key_gen_timeout`, `signing_timeout`, `oracle_timeout`, `voting_window`) or into the sentinel's `engine`, for example while editing the sample or after a copy-paste slip. The service exits at startup and its log shows the key. `${NAME}` substitution applies only to `rpc`, `signer` and `database`, so the key has to be in the file literally.

## Considered and rejected

- A1 (trusted operator): the trigger is an operator mistake, as it was for F2-XC-001, which the team rated and fixed rather than excluding under A1.
- settled.md: nothing on configuration error text. The deliberately alarming warning text it lists is a different item.
- F2-XC-001: Fixed for the whole-document path and due to leave the folder as resolved. This path is narrower and was explicitly left unfiled, so no live row carries it.
- F3-XC-130: a different field (`rpc`) and a different mechanism (alloy's IPC fallback quoting the URL).
- "The `url` crate never quotes the URL" (F3-XC-130's observation): true for alloy's connect path. A serde-deserialized `Url` field goes through `url`'s serde implementation, which adds the input to its error, as the run below shows.

## Remediation options

1. Redact quoted values in `ParseError` before storing the message, keeping the key path and position (enough to locate the mistake). The bite check below does this. Tradeoff: a non-secret typo such as `voting_window = "six"` no longer shows its value.
2. Keep only the key path, the position and a generic description of the error class (type or value mismatch), with no serde message at all. Stricter, same tradeoff.
3. Give the typed fields custom deserializers that report key-free messages, as `Signer` does. Most precise, more code per field.

Tests to add: extend `config::tests::errors_do_not_contain_the_configuration` with a key-shaped value in a numeric field and in a `Url` field. No code is committed.
