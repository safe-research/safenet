## Claim

The engine is called exactly once per proposal. Any transport error, 5xx, malformed body or timeout maps to `CheckOutcome::Unknown`, and the FSM drops the request permanently — even when minutes of the commit window remain. The per-request timeout is ¾ of `(voting_window − 1)` configured block times (371 s with the sample config on Gnosis), which has no relation to the oracle's real `COMMIT_WINDOW`; the same value is sent to the engine as `x-request-timeout`, so the engine has zero margin to answer before the client gives up. The client is `reqwest::Client::new()`: redirects are followed (up to 10), `HTTP(S)_PROXY` environment variables are honoured, there is no connection cap, and `.json()` buffers an unbounded response body. Under A3 the engine is trusted, so these are robustness rather than security defects, but a transient engine restart during a busy period translates directly into missed votes.

## Trigger

The engine pod restarts for ten seconds while three proposals arrive: three connection-refused errors, three `Unknown`, three requests dropped although the commit window is minutes long. Or: the operator sets `voting_window = 100` on a deployment whose `COMMIT_WINDOW` is 10 blocks; checks that take 60 s are still "within timeout" but every commit they produce expires unsubmitted.

## Considered and rejected

- "Abstaining is the documented behaviour": it is, for a _malfunctioning_ engine; a bounded retry inside the window does not change that semantics.
- "The engine answering twice": impossible — one HTTP request yields one resume, and the resume carries the effect's own `request_id` (effect.rs:57-68), not anything from the response.

## Remediation options

1. Retry with backoff while `now + attempt_timeout < commit_deadline − margin`, using the onchain `COMMIT_WINDOW` read at startup; send the engine a slightly shorter `x-request-timeout` than the client timeout.
2. Build the client with `redirect::Policy::none()`, `no_proxy()`, a connection/idle cap, and read the body with a size limit.

Tests to add: engine test where the first attempt is refused and the second succeeds within the window.
