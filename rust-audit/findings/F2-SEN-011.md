Audited commit: `fe9e84c` (exposed by the contract comments rewritten in PR #914; the Solidity code itself is unchanged and receives no finding).

## Claim

The delta rewrites the comments on `timeoutArbitration`/`markOutOfScope` to retract the "every committed bond returns in full" reading: a committer that never revealed was already slashed `slashAmount` when `finalize()` froze the request, and "that slash stands -- it is not refunded here". The sentinel's `handle_arbitration_timeout` still carries the old reading in its doc ("no side is established, so every committed bond returns in full via `claim()` … there is no winning side and no slash to record") and records `ResolvedOutcome::Timeout`, never `dispute_bond_slashed_amount`. The mismatch is observable for a sentinel that enters `WaitingForDisputeResolution` without having revealed — reachable through the recovery branch of `handle_dispute_triggered` from `CollectingVotes { self_revealed: false }` (e.g. a `DisputeTriggered` delivered by a warp before the reveal-deadline `NewBlock`): its `claim()` returns `bondTarget − slashAmount`, but the metrics report a clean timeout and no slash. The `Claim` action itself is correct, so this is documentation and observability drift, not a funds defect.

## Trigger

`H` commits, its `Reveal` is not mined before `revealDeadline`; the process is down across `revealDeadline`; a third party finalizes into `FROZEN`. On restart the warp page carries `DisputeTriggered` while the restored snapshot is `CollectingVotes { self_revealed: false }` → `WaitingForDisputeResolution` (claim 5). The arbitrator never rules; someone calls `timeoutArbitration`; `ArbitrationTimedOut` → `handle_arbitration_timeout` emits `Claim` and `requests_resolved_total{Timeout}` (claim 2). `claim()` returns `bondTarget − slashAmount` (claim 4); `dispute_bond_slashed_amount` is never recorded and the doc promised a full refund.

## Considered and rejected

- "The Solidity comment is the only thing that changed": true, and Solidity receives no finding; the Rust doc and metric were already inaccurate against the code and are now inaccurate against the reference documentation as well, which is what makes it worth a line in the report.
- "The normal route never gets here": `finalize()` only enters `WaitingForOutcome` with `self_revealed` (`service.rs:653`), so on the normal route the sentinel did reveal and the full-refund reading is right; the recovery route (claim 5) is the exception, and it exists precisely to avoid stranding a bond.

## Remediation options

1. Reword the doc at `service.rs:550-557` (and the `WaitingForDisputeResolution` doc in `state.rs:81-86`) to state the non-revealer caveat; carry a `self_revealed` flag into `WaitingForDisputeResolution` and record `dispute_bond_slashed_amount(slash_amount)` in `handle_arbitration_timeout` when it is false.
2. Alternatively surface the slash through a distinct `ResolvedOutcome` (e.g. `TimeoutRevealMissed`), mirroring `RevealMissed` in `handle_oracle_result`.

Tests to add: flow test driving `DisputeTriggered` into `CollectingVotes { self_revealed: false }` then `ArbitrationTimedOut`, asserting the slash metric (or outcome label) is recorded. No code is committed.

## Critic (C2-SEN-Δ)

Own reading first. `handle_arbitration_timeout` (`service.rs:563-593`) claims from any tracked state and records only `ResolvedOutcome::Timeout` (`585`); `dispute_bond_slashed_amount` is recorded in `handle_resolved` alone (`535`). Onchain the non-revealer's `slashAmount` is transferred at `finalize()` (`SentinelOracleRequests.sol:198-201`, `SentinelOracle.sol:279-281`) and kept at `claim` (`Requests.sol:294-295`, `SentinelOracle.sol:312`); `timeoutArbitration`/`markOutOfScope` refund only the fee (`Requests.sol:222-236`). The Rust doc at `550-557` ("no side is established … no slash to record") and the `WaitingForDisputeResolution` doc at `state.rs:81-86` ("confirmed both sides had revealed votes") are false on the recovery route; the `Claim` action is correct.
